# Bonsai 2 27B @ V100 16GB：优化前 vs 现在（一页纸）

数据来源：`RESULTS-ORIPOIN-PICKS-20260926.md` §1（"旧运行时"= 上游 bonsai-demo 运行时的实测）、
各节 A/B 表、以及 2026-09-27 在生产配置上的复测（`work\tmp\agent-turn-bench.py`、
`prefill-probe.py`、`test-backend-ops perf`）。

## 1. 硬指标（同机同模型族，ctx 131072 + q8_0 KV）

| 指标 | 最开始（上游运行时） | 现在 | 变化 |
|---|---|---|---|
| 预填充 12K 提示 | **175.8 t/s** | **854.1 t/s**（12K 探针、ub=1024 生产档；同档复测 848~873） | **4.9×** |
| 预填充 55.5K 提示 | **13.55 t/s** | 681.1 t/s（同 ctx 探针） | **50×** |
| 预填充 100K 提示 | （塌到不可用） | 610~740 t/s | — |
| 解码 12K（4 任务均值，无 MTP） | 44.15 t/s | 45.75 → 53~60 t/s（开 MTP 后） | +26~38%（相对 44.1 t/s 基准，随负载） |
| 解码 100K | — | 26~35 t/s（低/高接受率） | — |
| 显存（ctx 131072） | 15,847 MiB（上游运行时，同 ctx 预填充掉到 175.8 t/s） | 13,952~13,980 MiB（q8_0 KV + MTP，三档 ub 实测；探针口径 14,395） | 约 −1.9 GiB |
| 上下文 | 131072（但跑不动） | 131072 可用；另有 262144 预设 | — |
| PPL（2-chunk 语料 / q8_0，PQ2_0 → PTQ1_0） | 7.1131 | **7.1131**（逐位一致） | 无损 |

> 另有一组 50K 语料的 PPL 4.6649↔4.6649，那是 Volta FA 移植（RESEARCH §17）与
> q8_0-vs-q4_0 KV 的 A/B，不是 PTQ1_0 的等价性证据。

最开始那份"175.8 t/s / 55K 时 13.55 t/s"不是模型慢，而是 **FA 内核要把整段会话的 q8_0 KV
反量化成 f16**（ctx 131072 时 ~512 MiB，每个 op 重做一遍）→ 显存压爆 → WDDM 分页。

## 2. 逐项贡献（每一项都有 A/B 数据）

| 改动 | 贡献 |
|---|---|
| ① tile/mma FA 直读 q8_0 KV（oripoin `6ae7cbeb8` 等 9 个提交） | 预填充 **5.2×**（12K）、50×（55K）、显存 −1.9 GiB |
| ② PTQ1_0 内核栈整栈移植（planar 激活布局 + 专用 mat-vec） | pp16384 +3.4%、tg128 +6.4%、权重 −1.17 GiB、PPL 逐位一致 |
| ③ sm70 D256 Split-D prefill FA（自己移植的） | pp16384 +8%、pp32768 +13.8%；同形状比 stock 快 **1.85×** |
| ④ MTP 草稿头嫁接进主 GGUF + 草稿 micro-batch 修复 | 解码 **+26~38%**；带 MTP 的 12K 预填充 522→802 t/s |
| ⑤ Volta hs=256 FA 配置重调 + np>1 栅栏 UB（上游 #27955） | 消除 8576 个 UB；PPL 逐位一致 |
| ⑥ GDN 列并行 cols_per_warp 1→4 | 预填充全档 +2.6~2.8% |
| ⑦ ubatch 分档（32K/64K → 2048） | 短档预填充 +7.4%、解码 +12~25% |

## 3. 配套体验（最开始是 LM Studio 手点，现在）

* 自建控制台（8090）：实时 tok/s、首 token、预填充/解码分列、显存拆分、GPU 利用率/温度/功耗、
  上下文与缓存命中显示；一键启停、预设一键套用、模型参数可视化调整。
* 「一键接入 CC Switch / Codex」：刷新供应商条目 + 修 config.toml（含四档思考目录）+ 自检。
* 桌面快捷方式、退出时一键卸载模型、一键卸载服务。
* 预设按实测定标：32K/64K（ub 2048、MTP）、Agent 128K（按多轮 agent 负载的实测形态定标）、256K 极限档。

## 4. 诚实结论

* **预填充**从"不可用"变成"够用且接近上限"：剩下的时间花在小 batch 的 GPU 空转（~55% 墙钟）和
  已经跑到 DRAM 65% 的 GEMM 上，继续抠的收益都在 1% 量级。
* **解码**提升主要来自 MTP（+26~38%）与 PTQ1_0（+6%），本质是带宽受限（5.95 GiB 权重 × 每秒 token 数），
  已经到 V100 的实用区间。
* 期间也否证了一批方向（chunked GDN、KVMem、PTQ1_0 MMQ、KV 均值中心化、解码专用内核、融合小 m GEMM…），
  都留在 RESEARCH 文档里，避免重复投入。
